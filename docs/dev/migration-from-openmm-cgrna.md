# Migration From OpenMM-CGRNA

This developer-only document will track how legacy `OpenMM-CGRNA` behavior maps into the new `cranberry-rna` package.

Initial decisions:

- Temporary reference outputs should be generated from `CRANBERRY_workshop/cranberry-workshop-919771f4-gpu/`, not from the full legacy repo by default. See `docs/dev/reference-output-generation.md`.

- `D_CGRNA` is removed.
- Old `core.*` imports are not supported.
- v1 supports canonical CRANBERRY only, not public 5SPN/RACER APIs.
- Migration guidance should document important old commands and their new equivalents.
- Changes to legacy parameter files during construction of `cranberry-v1.h5` should be recorded here.

## Phase 2 Packaged Assets

Initial packaged assets were copied from the GPU workshop where available:

- `cranberry0.2.19.h5` -> `cranberry/data/forcefields/cranberry-v1-alpha.1.h5`
- `6spn.vs.xml` -> `cranberry/data/xml/cranberry.xml`
- `157d_cg_vs_conect.pdb` -> `cranberry/data/examples/157d_cg_vs_conect.pdb`
- `1zih_cg_vs_conect.pdb` -> `cranberry/data/examples/1zih_cg_vs_conect.pdb`

Additional fixtures from legacy reference data:

- `1l2x_cg_vs_conect.pdb` copied from `OpenMM-CGRNA/data/pdb/cg_6spn/`.
- `2ntCG_cg_vs_conect.pdb` generated by extracting residues 1-2 from `157d_cg_vs_conect.pdb`, preserving only `CONECT` records among retained atoms. Existing 6SPN `2ntCG` files lacked `BC`/`BN` virtual sites, so they were not canonical v1 fixtures.

## Phase 2 H5 Normalization

`cranberry-v1-alpha.1.h5` is now a merged canonical model asset. It contains:

- nonbonded/base/WCA parameters from `cranberry0.2.19.h5`
- bonded, dihedral, angle, and sugar-pucker parameters from `6spn.h5`
- HDF5 metadata recording `bonded_source`, `nonbonded_source`, `cranberry_model`, and `angle_scaling_baked_in`

The legacy `run_rna.py` default `--angle-scaling 0.1` is absorbed by multiplying angle spring constants inside the packaged alpha H5 file. This keeps the public API simple: users choose the model, not an additional angle-scaling runtime knob.

During alpha development, this user-facing file can be replaced as the canonical alpha model evolves. Once a package version is externally released, changes to the packaged model asset should be accompanied by a new package version.

## Phase 2 API Mapping

Legacy reference command shape:

```bash
D_CGRNA=/path/to/OpenMM-CGRNA python core/run_rna.py \
  --reso 6spn \
  --pucker-mode all-log \
  --base-form aniso \
  --spline-reso high \
  --nonbonded-para data/para/h5/cranberry0.2.19.h5 \
  --base-para data/para/h5/cranberry0.2.19.h5 \
  --angle-scaling 0.1
```

New package direction:

```python
from openmm import app, unit
from cranberry import CranberryForceField

pdb = app.PDBFile("input_cg_vs_conect.pdb")
ff = CranberryForceField()
system = ff.createSystem(
    pdb.topology,
    positions=pdb.positions,
    temperature=298 * unit.kelvin,
    salt_concentration=150 * unit.millimolar,
)
```

For energy decomposition:

```bash
cranberry energy input_cg_vs_conect.pdb --platform CPU --json
```

## Phase 2 Energy Reference Generation

The CPU energy regression constants are generated from the GPU workshop copy of `OpenMM-CGRNA` with:

```bash
run_rna.py \
  --dry-run --post-run-reporting --use-pdb \
  --reso 6spn \
  --pucker-mode all \
  --base-form aniso \
  --spline-reso high \
  --nonbonded-para data/para/h5/cranberry0.2.19.h5 \
  --base-para data/para/h5/cranberry0.2.19.h5 \
  --platform CPU \
  --temp 298 \
  --salt 150 \
  --angle-scaling 0.1
```

The legacy output splits sugar energy into `pucker` and `terminal_U3`; Cranberry reports those together as `pucker` for the Phase 2 energy API. The regression path uses the virtual-site coordinates provided in the canonical input PDB, matching the legacy post-run energy evaluator.
