CRANBERRY OpenMM Collinear Stacking Review

Developer review for the stacking numerical-stability fix tracked in GitHub issue #20. The change removes the singular OpenMM dihedral() primitive from the stacking normal-orientation expression while preserving the same analytic value away from singular geometries.

Scope

Root Cause

The old stacking expression attempted to avoid collinear dihedrals with select(sin(A)*sin(B), full, partial). OpenMM documents select(x,y,z) as exact-zero selection, so near or at 180 degrees sin(pi) can be a tiny nonzero value and select the branch containing dihedral(). In CustomHbondForce, a singular dihedral() can also contaminate force derivatives even when it appears in an unselected branch.

cos_normal_psi=select(sin(D2D1A1)*sin(D1A1A2), cos_normal_psi_full, cos_normal_psi_partial);
cos_normal_psi_full=sin(D2D1A1)*sin(D1A1A2)*cos(phi)-cos(D2D1A1)*cos(D1A1A2);
cos_normal_psi_partial=-cos(D2D1A1)*cos(D1A1A2);
D2D1A1=angle(d2, d1, a1); D1A1A2=angle(d1, a1, a2); phi=dihedral(d2, d1, a1, a2);

Replacement Formula

The stacking term needs the cosine of the relative base-normal orientation, not the signed dihedral angle itself. The new expression computes the same normal dot product directly from distances:

cos_normal_psi=
(
  distance(d2,a1)^2
+ distance(d1,a2)^2
- distance(d2,a2)^2
- distance(d1,a1)^2
) / (2*distance(d1,d2)*distance(a1,a2));

This follows from expanding squared distances. The numerator cancels to 2*(d2-d1) dot (a2-a1), so the normalized expression is the cosine between the donor and acceptor normal vectors. It is algebraically equivalent to the old angle/dihedral reconstruction wherever the dihedral is defined, and remains well-defined at collinearity as long as each normal vector has nonzero length.

Production Code

The production edit is confined to stacking. The g1 and g2 angle-gate terms are left unchanged; only g3's normal orientation input avoids dihedral().

f"g3=1/2*(tanh(theta_sens*({g3_sign}cos_normal_psi-cos(psi0)))+1); "
"cos_normal_psi=(distance(d2,a1)^2+distance(d1,a2)^2-distance(d2,a2)^2-distance(d1,a1)^2)/(2*distance(d1,d2)*distance(a1,a2)); "
"D2D1A1=angle(d2, d1, a1); D1A1A2=angle(d1, a1, a2); "

Risks And Follow-Up

  • The fix intentionally changes the expression graph, but not the analytic stacking energy away from singularity. Off-singularity force equivalence was checked on CPU OpenMM.
  • CUDA was not available in the local conda environments, so CUDA validation remains follow-up.
  • Pairing still contains angle/dihedral constructs. This report only addresses stacking, which is the implicated force family for the collinear base-normal issue.
  • The checkout contains unrelated pre-existing dirty files; the PR should stage only the files listed in this report.
