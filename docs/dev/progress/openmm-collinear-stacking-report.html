CRANBERRY OpenMM Collinear Normal-Orientation Review

Developer review for the stacking numerical-stability fix tracked in GitHub issue #20 and the matching pairing normal-orientation follow-up. The change removes the singular OpenMM dihedral() primitive from donor/acceptor base-normal cosine expressions while preserving the same analytic value away from singular geometries.

Root Cause

The old stacking expression attempted to avoid collinear dihedrals with select(sin(A)*sin(B), full, partial). The pairing h gate used the same normal-orientation reconstruction. OpenMM documents select(x,y,z) as exact-zero selection, so near or at 180 degrees sin(pi) can be a tiny nonzero value and select the branch containing dihedral(). In CustomHbondForce, a singular dihedral() can also contaminate force derivatives even when it appears in an unselected branch.

cos_normal_psi=select(sin(D2D1A1)*sin(D1A1A2), cos_normal_psi_full, cos_normal_psi_partial);
cos_normal_psi_full=sin(D2D1A1)*sin(D1A1A2)*cos(phi)-cos(D2D1A1)*cos(D1A1A2);
cos_normal_psi_partial=-cos(D2D1A1)*cos(D1A1A2);
D2D1A1=angle(d2, d1, a1); D1A1A2=angle(d1, a1, a2); phi=dihedral(d2, d1, a1, a2);

Replacement Formula

The stacking g3 term and pairing h term need the cosine of the relative base-normal orientation, not the signed dihedral angle itself. The new expression computes the same normal dot product directly from distances:

cos_normal_psi=
(
  distance(d2,a1)^2
+ distance(d1,a2)^2
- distance(d2,a2)^2
- distance(d1,a1)^2
) / (2*distance(d1,d2)*distance(a1,a2));

This follows from expanding squared distances. The numerator cancels to 2*(d2-d1) dot (a2-a1), so the normalized expression is the cosine between the donor and acceptor normal vectors. It is algebraically equivalent to the old angle/dihedral reconstruction wherever the dihedral is defined, and remains well-defined at collinearity as long as each normal vector has nonzero length.

Physics Audit

In the pairing expression, the particle names map to base sites as follows:

Expression nameCranberry sitePhysical role
d1donor BCdonor base center
d2donor BNdonor base-normal site
d3donor B1donor in-plane base reference site
a1acceptor BCacceptor base center
a2acceptor BNacceptor base-normal site
a3acceptor B1acceptor in-plane base reference site

The replacement therefore acts only on the angle between the two out-of-plane normal vectors d1->d2 and a1->a2. This is the quantity used by stacking's g3 gate and pairing's h gate.

stacking: g3 = tanh(... sign*cos_normal_psi - cos(psi0) ...)
pairing:  h = tanh(... psi_sign*cos_normal_psi - cos(psi0) ...)

The quoted pairing torsions are different:

D3D1D2A1 = dihedral(d3,d1,d2,a1)
A3A1A2D1 = dihedral(a3,a1,a2,d1)

These terms use each base's in-plane B1 reference together with its normal vector and the partner base center. They gate the signed local phase of the donor and acceptor geometry:

g3 = tanh(... cos(D3D1D2A1 - phi1) - cos(dphi1) ...)
g4 = tanh(... cos(A3A1A2D1 - phi2) - cos(dphi2) ...)

The packaged pairing table confirms that phi1 and phi2 are genuine phase targets, not just zero-or-pi alignment constants. Across the 25 pairing rows, example values include phi1=1.088, 2.837, 4.703 and phi2=1.314, 3.520, 5.095 radians. A distance-only dot product would erase handedness and cannot represent cos(phi-phi0) for arbitrary phi0 without a separate signed construction. Those torsions remain unchanged in this PR.

Production Code

The merge resolution keeps the collaborator's fused stacking force and packed-pairing force. A small helper now emits the shared distance-dot expression for stacking's default particle names and pairing's donor/acceptor names. The signed pairing torsions D3D1D2A1 and A3A1A2D1 remain unchanged because they encode different phase gates, not a plain normal-vector cosine.

def _normal_cosine_expression(d1="d1", d2="d2", a1="a1", a2="a2"):
    return (
        f"(distance({d2},{a1})^2+distance({d1},{a2})^2"
        f"-distance({d2},{a2})^2-distance({d1},{a1})^2)"
        f"/(2*distance({d1},{d2})*distance({a1},{a2}))"
    )

... + f"cos_normal_psi={_normal_cosine_expression(d1, d2, a1, a2)}; "

Risks And Follow-Up

  • The fix intentionally changes the expression graph, but not the analytic stacking or pairing normal-orientation energy away from singularity. Off-singularity force equivalence was checked on CPU OpenMM.
  • The fused stacking scale parameters remain intentionally internal. They default to one during dynamics and are used to isolate stacking35, stacking55, and stacking33 for detailed energy reporting.
  • CUDA was not available in the local conda environments, so CUDA validation remains follow-up.
  • Pairing still contains the signed phi1 and phi2 dihedral gates. Those are not replaced by this distance-dot identity because they are not plain normal-vector cosine terms.
  • The checkout contains unrelated pre-existing dirty files; the PR should stage only the files listed in this report.
