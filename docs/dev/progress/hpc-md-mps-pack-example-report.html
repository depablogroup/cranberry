HPC MD MPS Pack Example Report

Scope

This change adds a generic Slurm example for packing multiple independent cranberry md runs onto one allocated GPU with CUDA MPS. The submitter accepts CLI-style options such as repeated --pdb, --steps, --platform, and --output-root, then launches one plain cranberry md process per input PDB directly. By default, every input PDB is launched concurrently inside the allocation. The existing L40S and production submitters are left unchanged. The example is intended for copy-and-adapt HPC usage, not as a public Cranberry API change.

Main-Branch Compatibility Check

Local main does not contain scripts/hpc/; the HPC launcher tree is branch-added. The generic example is self-contained and avoids setting PLATFORM_PROPERTIES by default, because the optional --platform-property MD CLI path is branch-dependent relative to local main. The default example path uses stable MD options: input PDBs, output directory, steps, records, model, temperature, salt, timestep, platform, and optional PBC.

  • scripts/hpc/submit_md_mps_pack_example_slurm.sh: new generic Slurm example submitter.
  • scripts/hpc/README.md: added usage and adaptation notes for independent MD packing with CUDA MPS.

Key Script Path

The example resolves the Cranberry checkout, parses user-friendly submit options, and either prints a dry-run sbatch command or submits itself. Inside Slurm it prepares the Python environment, starts CUDA MPS when available, and launches cranberry md directly for each PDB. 

scripts/hpc/submit_md_mps_pack_example_slurm.sh \
  --pdb /path/a_cg_vs_conect.pdb \
  --pdb /path/b_cg_vs_conect.pdb \
  --steps 500000 \
  --platform CUDA \
  --output-root runs/md_pack_example

if [ -z "${SLURM_JOB_ID:-}" ]; then
    echo "Submitting $JOB_NAME to Slurm"
    submit_self
    exit 0
fi

prepare_python_env

cmd=(
    "$CRANBERRY_BIN" md "$pdb_path"
    --steps "$STEPS"
    --output-dir "$run_dir"
    --platform "$OPENMM_PLATFORM"
)

"${cmd[@]}" > "$run_dir/md.log" 2>&1 &

Regression Coverage

The new test file intentionally avoids GPUs, Slurm, and CUDA. It verifies that tracked HPC shell scripts parse with bash -n, then runs the generic submitter with --dry-run and packaged example PDBs to ensure the CLI-style path generates an sbatch command with the expected scheduler arguments. 

def test_hpc_shell_scripts_parse_with_bash() -> None:
    for relative_path in HPC_SHELL_SCRIPTS:
        result = subprocess.run(["bash", "-n", str(script)], ...)
        assert result.returncode == 0

def test_md_mps_pack_example_slurm_dry_run(tmp_path: Path) -> None:
    result = subprocess.run([str(script), "--dry-run", "--pdb", str(pdb_a), ...], ...)
    assert "dry-run sbatch:" in result.stdout
    assert "--gres=gpu:1" in result.stdout

def test_md_mps_pack_example_slurm_runs_md_directly() -> None:
    assert '"$CRANBERRY_BIN" md "$pdb_path"' in script_text
    assert "run_cranberry_md_mps_pack.sh" not in script_text

Risks And Follow-Up

  • The example is not a real Slurm/CUDA integration test; it checks the portable dry-run path only.
  • Cluster-specific resource choices still need local tuning for CPU count, memory, walltime, partition, and account.
  • The example intentionally has no automatic timeout/resubmission policy; production wrappers can add that after site validation.
  • GPU utilization improvements should be measured per system with nvidia-smi, per-run logs, and wall-clock throughput before increasing the number of PDBs packed into one allocation.
