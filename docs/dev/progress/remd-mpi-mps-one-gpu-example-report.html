REMD MPI MPS One-GPU Example Report

This report covers the small HPC example that shows how to run the README periodic REMD workflow with MPI ranks packed onto one Slurm GPU through CUDA MPS.

Changes

  • Added scripts/hpc/submit_remd_mpi_mps_one_gpu_example_slurm.sh, a minimal Slurm batch script.
  • Added a short README pointer after the existing periodic REMD example.
  • Added focused script tests in tests/test_hpc_scripts.py.
  • Guarded the top-level compatibility __init__.py so pytest can collect tests when it imports that file as a standalone module.

Important Code Paths

The example script keeps the workflow close to the public CLI example:

srun -n "$N_REPLICAS" "$CRANBERRY_BIN" remd "$PDB_PATH" \
    --extra-start-pdb "$EXTRA_START_PDB" \
    --periodic \
    --steps "$STEPS" \
    --n-replicas "$N_REPLICAS" \
    --platform CUDA \
    --output-dir "$OUTPUT_DIR"

The only runtime setup around the command is the one-GPU Slurm allocation and CUDA MPS lifecycle:

#SBATCH --gres=gpu:1
#SBATCH --ntasks=8

export OPENMMTOOLS_ENABLE_MPI="${OPENMMTOOLS_ENABLE_MPI:-1}"
export CUDA_MPS_PIPE_DIRECTORY="${CUDA_MPS_PIPE_DIRECTORY:-/tmp/cranberry-remd-mps-${USER:-user}-${SLURM_JOB_ID:-$$}}"
export CUDA_MPS_LOG_DIRECTORY="${CUDA_MPS_LOG_DIRECTORY:-$OUTPUT_DIR/mps-log}"
nvidia-cuda-mps-control -d

Risks

  • The script is intentionally an example, not a production launcher. Cluster-specific account, partition, module, and environment setup remain user responsibility.
  • The example assumes Slurm exports a single allocated GPU to the job. Sites with unusual GPU binding policies may need local edits.
  • CUDA MPS requires NVIDIA tooling on the compute node; the script warns and continues if nvidia-cuda-mps-control is unavailable.
