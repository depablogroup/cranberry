REMD Langevin Default Report

This change updates Cranberry REMD defaults after local MPI+MPS profiling showed that the previous GHMC move and short exchange interval made OpenMMTools propagation substantially slower than direct MPS MD for the bundled ggcGCAAgcc benchmark.

Behavior Change

  • Default REMD move changed from GHMCMove to normal OpenMMTools LangevinDynamicsMove.
  • Default REMD exchange interval changed from swap_steps=100 to swap_steps=5000.
  • Each thermodynamic temperature receives its own Langevin move with Cranberry's length-dependent friction calculated at that temperature.
  • REMD Langevin moves use reassign_velocities=True, matching the OpenMMTools alanine REMD benchmark style and keeping velocities thermalized to the current temperature after exchanges.
  • The experimental positions-only move tested during profiling is not used.

Key Code Path

move_temperatures = _expected_temperatures(ladder_spec)
collision_rates = tuple(
    calculate_langevin_friction(pdb.topology, system, temperature * unit.kelvin)
    for temperature in move_temperatures
)
move = [
    mcmc.LangevinDynamicsMove(
        timestep=config.timestep_femtosecond * unit.femtosecond,
        collision_rate=collision_rate,
        n_steps=config.swap_steps,
        reassign_velocities=True,
    )
    for collision_rate in collision_rates
]

The provenance writer records mcmc_move and the per-temperature langevin_collision_rate_per_ps list in args.json.

Risk

This changes the default sampler from a Metropolized GHMC move to a standard Langevin dynamics move. Langevin is the same integrator family used by Cranberry MD and is a normal OpenMMTools REMD choice, but it does not provide GHMC's Metropolis correction for finite-timestep integration error. Users can still tune --swap-steps; an explicit move-selection API is deferred until there is a concrete need.
