REMD MPI Restart Reproducer Report

This report records the regression test added for GitHub issue #9. The test intentionally uses a real OpenMMTools REMD storage file and a real OpenMPI/mpi4py launch instead of fake reporter classes.

Change

  • Added test_run_remd_mpi_restart_reopens_existing_storage in tests/test_remd.py.
  • The test creates a one-step serial REMD storage file with run_remd.
  • It then launches mpirun --oversubscribe -n 2 python -m cranberry.cli.main remd ... --restart-from output.nc with OPENMMTOOLS_ENABLE_MPI=1. The oversubscribe flag lets GitHub-hosted runners start two tiny CPU ranks even when OpenMPI detects only one default slot.
  • Updated GitHub Actions CI to install openmpi and mpi4py so the regression runs in CI.

Expected Current Result

The test is expected to fail on current main. It reproduces the same OpenMMTools restart-open failure seen in production:

OSError: [Errno -101] NetCDF: HDF error: '.../output.nc'
openmmtools.multistate.multistatesampler.py: from_storage
mpiplus.run_single_node(... sampler._reporter.open, mode='a' ...)

Validation

  • conda run -n cranberry-dev which mpirun found /bin/mpirun.
  • conda run -n cranberry-dev python -c "import mpi4py, openmmtools, mpiplus" passed with mpi4py 4.1.2 and OpenMMTools 0.26.0.
  • conda run -n cranberry-dev mpirun -n 2 python -c "from mpi4py import MPI; ..." reported size 2.
  • conda run -n cranberry-dev python -m pytest -q tests/test_remd.py::test_run_remd_mpi_restart_reopens_existing_storage failed as intended with the NetCDF HDF restart error.

Follow-Up

The next fix should make this test pass by closing Cranberry's read-only validation reporter before storage restore and by synchronizing MPI restore/open ordering before rank 0 opens append mode.
