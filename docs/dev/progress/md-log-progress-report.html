MD Log Progress Option Review

Developer review note for adding an opt-in OpenMM progress column to Cranberry MD logs.

Code changes

  • Added run_md(..., log_progress=True) and forwarded it to OpenMM StateDataReporter(progress=...).
  • Recorded log_progress in args.json provenance.
  • Included log_progress in restart compatibility checks because appending to a log with a different column layout would corrupt the CSV-like output contract.
  • Added CLI flag cranberry md --no-log-progress to disable the default progress column.
  • Updated public output/tutorial docs to describe the default Progress (%) log column and opt-out flag.

Validation

  • python -m pytest -q tests/test_md.py::test_run_md_writes_default_outputs tests/test_md.py::test_run_md_can_omit_log_progress tests/test_cli.py::test_cli_md_help tests/test_cli.py::test_cli_md_no_log_progress_option passed: 4 tests in 14.66 s.
  • python -m pytest -q tests/test_md.py tests/test_cli.py -m 'not remd' passed: 29 tests, 5 deselected in 96.73 s.
  • A previous full python -m pytest -q tests/test_md.py tests/test_cli.py run reached the REMD tests, which require openmmtools; that optional dependency is not installed in this environment.

Risks

  • The OpenMM progress column is now the first column in the default log column set; users who need the earlier column layout can pass --no-log-progress.
  • Restart compatibility now rejects mismatched log_progress settings to avoid appending rows with incompatible headers.
