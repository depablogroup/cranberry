CRANBERRY release audit: high-severity blockers

Date: 2026-08-31

This report records the three high-severity release fixes requested after the pre-publication audit.

Fixes

  • REMD now executes exactly the requested integration-step count. Full exchange intervals run normally, and a shortened final Langevin move handles a non-divisible remainder.
  • Canonical validation now checks the complete per-residue and inter-residue bond graph, rejects duplicate bead names, and reports missing or unexpected topology bonds.
  • The README GPU installation recipe installs pip and the required h5py dependency before using the intentional --no-deps editable install.

Review paths

  • cranberry/remd.py: exact step planning and shortened-final-move execution.
  • cranberry/validation.py: canonical topology graph construction and comparison.
  • tests/test_remd.py and tests/test_validation.py: focused regressions.
  • README.md: clean GPU installation recipe.

Validation

Focused tests and the full CPU-first suite should be run in the Python 3.11 cranberry-dev environment. The audit host did not provide that environment; an older OpenMM environment was available only for API inspection and was not used as release validation.

Static checks completed on the audit host: Python compilation, shell syntax, privacy scan, relative-link audit, model/XML hash verification, and clean-worktree checks before editing.

Risks

The REMD final iteration uses a different n_steps value from the normal exchange interval; provenance continues to record the requested total, interval, and iteration count. The topology validator intentionally enforces the canonical graph generated by the package’s coarse-graining/preparation workflows.
