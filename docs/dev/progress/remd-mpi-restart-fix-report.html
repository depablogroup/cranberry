REMD MPI Restart Fix Report

This report covers the minimal fix for the MPI REMD NetCDF restart-open failure reproduced by test_run_remd_mpi_restart_reopens_existing_storage.

Problem

Current cranberry remd --restart-from output.nc opened a Cranberry-owned read-only MultiStateReporter to validate the stored temperature ladder, then called OpenMMTools ParallelTemperingSampler.from_storage() while that reporter was still open. Under MPI, OpenMMTools also reopens the same storage in read mode on all ranks and then rank 0 opens append mode. This can fail with NetCDF: HDF error.

Fix

  • Close Cranberry's read-only validation reporter in a finally block before sampler restoration.
  • Add a tiny MPI runtime detector using optional mpiplus.
  • Keep non-MPI behavior delegated to OpenMMTools from_storage().
  • For MPI restarts, mirror OpenMMTools restore: read/restore/close on all ranks, run an MPI barrier, then let rank 0 reopen append mode with sync_nodes=True.

Key Code

try:
    stored_temperatures = _read_temperatures_from_reporter(reporter)
    ...
finally:
    _close_if_present(reporter)

sampler = _sampler_from_storage(sampler_cls, output_netcdf_path, mpiplus, mpi_runtime)
reporter.open(mode='r')
sampler = sampler_cls._instantiate_sampler_from_reporter(reporter)
sampler._restore_sampler_from_reporter(reporter)
reporter.close()

_mpi_barrier(mpiplus)
mpiplus.run_single_node(0, sampler._reporter.open, mode='a', sync_nodes=True)

Scope

This intentionally does not add the broader HPC launch scripts, platform-property plumbing, or runtime metadata from the existing mitigation branch. It only changes REMD restart storage-open ordering.
