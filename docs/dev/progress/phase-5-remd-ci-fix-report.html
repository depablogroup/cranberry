Phase 5 REMD CI Fix Report

Most recent commit e635763 added REMD tests while the CI environment originally installed only .[dev]. The first attempted fix changed the pip editable install to .[dev,remd], but openmmtools is distributed for normal use through conda-forge, so a pip-only GitHub Actions environment can still fail while resolving the REMD extra.

Fix

  • Changed GitHub Actions to create an activated conda environment with conda-incubator/setup-miniconda.
  • Installed pip, setuptools, wheel, openmm, openmmtools, and the dev/documentation dependencies from conda-forge.
  • Installed the local cranberry package in a separate explicit step with python -m pip install --no-deps -e ".[dev,remd]" after conda dependency resolution, avoiding a second pip attempt to resolve conda-managed scientific packages while still installing cranberry itself.
  • Kept the REMD marker on CLI extraction tests because they create real REMD NetCDF files via run_remd; GitHub CI should now execute them in the conda environment.

Risk

Moderate. CI now depends on conda-forge availability, but that matches the dependency channel needed for openmmtools-backed REMD validation.

Validation

  • python -m pytest tests/test_cli.py::test_cli_help tests/test_cli.py::test_cli_remd_help -q
  • python -m pip install -e ".[dev,remd]" remains blocked locally by this environment's network tunnel and is no longer the CI install strategy.
