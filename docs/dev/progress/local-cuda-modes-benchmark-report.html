Local CUDA Modes Benchmark Report

This report records the local RTX 2060 benchmark harness and ggcGCAAgcc CUDA/MPS/REMD runs.

Implementation

  • Added benchmarks/benchmark_cuda_modes.py, a local YAML benchmark harness.
  • The harness samples nvidia-smi for mean/max GPU utilization and max memory.
  • MD rows record per-runner log speed and aggregate log/wall speed.
  • REMD rows parse OpenMMTools output_real_time_analysis.yaml; its timing_data.ns_per_day is aggregate REMD throughput.
  • The REMD benchmark can launch through mpirun --oversubscribe -n N with OPENMMTOOLS_ENABLE_MPI=1; --start-mps starts CUDA MPS for multi-rank GPU concurrency.
  • The benchmark default uses REMD --n-analysis 0, which still lets OpenMMTools write one final timing estimate. Cranberry's package default also remains n_analysis=0.

Notes

  • For REMD, OpenMMTools ns_per_day is aggregate speed across replicas. The report divides by MPI ranks to show per-runner speed.
  • Plain serial REMD is not the real multi-rank scenario; use MPI plus MPS. Without MPI, mpiplus uses a size-1 communicator and OpenMMTools runs serially.
  • The MPI+MPS JAX-CPU run wrote timing YAML but exited nonzero because Cranberry currently reads reporter thermodynamic states on non-root MPI ranks after sampling.
  • Raw run directories contain DCD/checkpoint/NetCDF/stdout/stderr artifacts and are intentionally separate from the compact YAML snapshots.
