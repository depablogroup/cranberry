CRANBERRY Benchmark Log-Log Update Review

Developer review for the benchmark presentation update: expanded fixture coverage, log-log SVG plotting, a shorter GPU label, and regenerated published benchmark artifacts.

Review Finding

No blocking issues found

The benchmark runner still generates JSON-first snapshots and publishes docs from those snapshots, but the visualization now matches the wider system-size range better. The main risk is the usual one for benchmark artifacts: the published snapshot is only as current as the last run on the target machine.

Scope

Implemented

  • Expanded the default CUDA benchmark suite to include rU40, 5ml7, and 2mi0.
  • Changed the benchmark SVG from linear scatter to a log-log line chart with dots at each measured system.
  • Added a compact GPU card label, rendered as 2060 for the RTX 2060 snapshot.
  • Regenerated the published benchmark JSON, markdown, and SVG artifacts.
  • Added a regression test for the new system fixtures and short GPU label helper.

Still out of scope

  • Multiple benchmark series for CPU, CUDA, and MPS side by side.
  • REMD benchmark publishing.
  • Automatic remote upload/publishing of benchmark snapshots from another machine.

Core Behavior

Benchmark Suite

The default benchmark suite now includes seven canonical systems instead of four. The new entries are the examples the user added to the repository: rU40, 5ml7, and 2mi0. The runner still times each system individually, then sorts the rows by nucleotide count before publishing.

SYSTEMS = {

Log-Log Plot

The previous linear scatter plot was too cramped for the broadened system-size range. The renderer now maps both axes through log10, labels the axes explicitly as log scale, draws a line through the ordered measurements, and keeps the individual dots visible on top of the line.

title = escape(f"CRANBERRY MD throughput: {snapshot.platform} {legend_label}{' + MPS' if snapshot.mps_enabled else ''}")

Published Snapshot

The regenerated current snapshot reflects the new fixture set and the short label. The docs now state log scale on both axes and point to the current GPU as 2060 instead of the full card name in the chart title.

Residual Risk

  • Benchmark freshness: the published snapshot is still a point-in-time artifact and must be rerun on each target machine if you want up-to-date throughput numbers.
  • Dataset completeness: the chart now spans more example systems, but it still represents a single GPU/card snapshot until other machines are published.

Recommendation

Approve this benchmark presentation update. It makes the current benchmark page more legible for the RNA system-size range and keeps the snapshot pipeline aligned with the docs-first workflow.
