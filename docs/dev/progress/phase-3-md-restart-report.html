CRANBERRY Phase 3 MD Restart Review

Developer review for the MD restart extension: checkpoint loading, CLI support, reusable final PDB connectivity, tests, and docs.

Review Finding

No blocking issues found

The restart implementation is small and fits the existing MD runner. It loads OpenMM checkpoints into a freshly constructed matching simulation, appends time-series outputs when present, creates missing time-series outputs with a warning, and updates latest-state files.

Scope

  • Added restart_from to create_simulation() and run_md().
  • Added cranberry md --restart-from checkpoint.chk.
  • Recorded structured restart metadata in args.json, including PDB hash, model, temperature, salt, timestep, platform, versions, restart source, and append behavior.
  • Archived distinct previous metadata files under args_history/.
  • Added restart compatibility checks: scientific/system mismatches are errors; platform/version mismatches are warnings.
  • Made final.pdb include topology CONECT records so it validates as canonical Cranberry input.
  • Added API and CLI restart tests, missing-checkpoint error test, and final-PDB validation test.

Important Code Paths

Checkpoint Loading

The simulation is still constructed from the current PDB/model/settings, then a checkpoint is loaded into that context. Missing checkpoint paths fail before outputs are written.

def create_simulation(..., restart_from: str | Path | None = None) -> app.Simulation:
    ...
    simulation.context.setPositions(pdb.positions)
    if restart_from is None:
        simulation.context.setVelocitiesToTemperature(temperature)
    else:
        restart_from = Path(restart_from)
        if not restart_from.exists():
            raise FileNotFoundError(f"Checkpoint not found: {restart_from}")
        simulation.loadCheckpoint(str(restart_from))
    return simulation

Canonical Final PDB

The first implementation wrote final coordinates with OpenMM's PDBFile.writeFile(), but that omitted CONECT records. The fix writes the coordinates to a buffer, inserts topology bonds as CONECT records, then writes END.

def _write_pdb_with_conect(path: Path, topology: app.Topology, positions) -> None:
    buffer = io.StringIO()
    app.PDBFile.writeFile(topology, positions, buffer, keepIds=True)
    lines = buffer.getvalue().splitlines()
    if lines and lines[-1].startswith("END"):
        lines = lines[:-1]
    for bond in topology.bonds():
        lines.append(f"CONECT{_pdb_serial(bond.atom1):5d}{_pdb_serial(bond.atom2):5d}")
    lines.append("END")
    path.write_text("\n".join(lines) + "\n")

Residual Risks

  • Checkpoint portability: OpenMM checkpoints are platform/system dependent. Users must restart with a compatible model, topology, and OpenMM platform.
  • Missing append targets: restart warns and creates missing output.dcd, log, or detailed.log. Those files then begin at the checkpoint step rather than step 0.
  • Short CI simulation: tests prove checkpoint loading and step continuation on CPU, not long production stability.

Recommendation

Approve this restart slice. It makes the existing checkpoint.chk useful, matches the legacy append-on-restart behavior for time-series outputs, preserves metadata history, checks restart compatibility, and fixes final.pdb so it preserves topology connectivity.
