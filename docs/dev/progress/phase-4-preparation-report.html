CRANBERRY Phase 4 Preparation Review

Developer review for the first Phase 4 slice: a real preparation/canonicalization workflow with optional terminal-phosphate insertion, plus the CLI, API, tests, and docs needed to expose it.

Review Finding

No blocking issues found

The slice is intentionally narrow. The current implementation now distinguishes a true no-op validation path from the phosphate-insertion path, and the main remaining risk is scope rather than immediate correctness: this still does not implement a full upstream coarse-graining pipeline.

Scope

Implemented

  • Added cranberry.prepare.prepare_structure() and PreparedStructureResult.
  • Added cranberry prepare and cranberry cg CLI commands.
  • Added a shared PDB writer that preserves CONECT records.
  • Added a validation-only no-op path for cranberry prepare/cranberry cg when no phosphate insertion is requested.
  • Added optional 5'-terminal phosphate insertion for chain-start residues missing P.

Still out of scope

  • Full upstream coarse-graining from atomistic or other non-canonical inputs.
  • Any richer model-specific phosphate placement heuristics.
  • REMD and the other optional v1 extras.

Core Behavior

Preparation Workflow

prepare_structure() now has two distinct modes. Without terminal-phosphate insertion it validates the canonical coarse-grained PDB and returns without writing any output file. With terminal-phosphate insertion it loads the input through OpenMM, rewrites the structure with canonical CONECT records, and validates the result again.

result = prepare_structure(
    "input_cg_vs_conect.pdb",
    add_terminal_phosphate=True,
    output_path="prepared.pdb",
)

5'-Phosphate Insertion

When add_terminal_phosphate=True, the workflow looks only at the first residue of each chain. If that residue already has a P bead, no insertion happens. If it is missing P, Cranberry synthesizes one new P atom, bonds it to the existing S3 bead, and increments the insertion count for that chain.

The placement heuristic is now a fixed v1 choice rather than an open modeling question. The inserted phosphate is placed at a fixed P-S3 distance of 0.45 nm. When a downstream phosphate is available, the direction is chosen to satisfy two angle targets at the terminal S3: angle(P, S3, S2) = 2.356 rad and angle(P, S3, next P) = 1.920 rad. When no downstream phosphate is available, Cranberry falls back to the single-angle construction against S2 only. This is deterministic and test-covered, and it is intended to stay stable as part of the package contract.

Algorithm Detail

The implementation lives in cranberry/prepare.py and has three nested steps:

  1. Detect whether the first residue of a chain is missing P. If not, return the topology unchanged for that chain.
  2. Gather the local geometric anchors: the current residue S2 and S3, plus the next available downstream P if one exists later in the same chain.
  3. Solve for a unit direction from S3 and place the new phosphate at S3 + direction * 0.45 nm.

In the two-angle branch, the code first builds an orthonormal local basis around the terminal sugar:

  • a is the normalized S3 -> S2 direction.
  • b is the normalized S3 -> next P direction.
  • c is the in-plane component of b orthogonal to a.
  • n is the plane normal from a x c.

The phosphate direction is then solved in that basis as d = x a + y c +/- z n, where:

x = cos(angle(P, S3, S2))
y = (cos(angle(P, S3, next P)) - x * dot(a, b)) / ||b - a * dot(a, b)||
z = sqrt(max(0, 1 - x^2 - y^2))

That construction guarantees the requested distance and both target angles when the local geometry is consistent enough to admit a solution. The code then chooses between the +z and -z branches deterministically by preferring the candidate with the larger z component in the lab frame. This is not a physical energy minimization; it is just a stable branch-selection rule so repeated runs place the bead identically.

If the two-angle solve is numerically ill-conditioned, for example because the downstream phosphate direction is nearly collinear with S3 -> S2 or the requested constraints are inconsistent in the local basis, Cranberry falls back to a single-angle construction. In that branch it picks an arbitrary but deterministic perpendicular direction to S3 -> S2 and uses:

direction = u * cos(2.356) + p * sin(2.356)

where u is the normalized S3 -> S2 direction and p is a deterministic perpendicular unit vector.

The behavior is intentionally conservative:

  • Only chain-start residues are eligible.
  • The default prepare path is deliberately a no-op and does not create a renamed copy.
  • Only missing P beads are inserted.
  • All other residues are left unchanged.
  • The resulting structure is revalidated before the command returns success.

What The Tests Actually Lock

  • The no-op path returns success without writing an output file.
  • The phosphate-writing path creates a real P-S3 bond and does not create the earlier serial-mapping bug that produced a spurious bond.
  • The written coordinates satisfy the current distance and angle targets within small tolerances.
  • The output still passes canonical PDB validation after insertion.

Residual Risk

  • Scope: this is the first preparation slice, not the full coarse-graining pipeline.
  • Geometry: the phosphate placement is a fixed deterministic heuristic. It satisfies the current distance/angle targets and is treated as part of the v1 contract.
