Core Behavior

Implementation Path

The cg command does not use Biopandas. It uses OpenMM's PDB parser because the workflow only needs the topology, residue names, atom coordinates, and bond graph. That keeps the implementation aligned with the rest of the package and avoids a second dependency for simple PDB ingestion.

from openmm import app, unit

from cranberry.pdbio import write_pdb_with_conect
from cranberry.validation import validate_canonical_pdb


def coarse_grain_structure(pdb_path, *, output_path=None, overwrite=True):
    pdb = app.PDBFile(str(pdb_path))
    topology, positions, residue_count, inserted_virtual_sites, missing_terminal_phosphates = _build_cg_topology(
        pdb.topology,
        pdb.positions,
    )
    write_pdb_with_conect(output_path, topology, positions)
    output_validation = validate_canonical_pdb(output_path)
    output_validation.raise_for_errors()
    return CoarseGrainResult(...)

Core Algorithm

The converter walks each chain and residue, maps canonical residue names (rA/rU/rG/rC) to the CRANBERRY bead order, copies backbone and base bead coordinates from the atomistic structure, and then synthesizes the virtual sites. BC is the center of geometry of the three base beads. BN is a fixed out-of-plane heuristic built from the base triangle with a constant cross-product scale.

for atom_name in _OUTPUT_ATOM_ORDER[residue_name]:
    if atom_name == "P":
        ... copy phosphate if present ...
    elif atom_name == "BC":
        position = _virtual_site_cog(new_positions_by_name, residue_name)
    elif atom_name == "BN":
        position = _virtual_site_normal(new_positions_by_name, residue_name)
    else:
        source_atom_name = _SOURCE_ATOMS[residue_name][atom_name]
        position = source_positions[source_atom.index]

After atom placement, the code writes the expected bead bonds, including the backbone link between adjacent residues and the BC/BN connectivity, then validates the output as a canonical prepared PDB.

Residue Mapping

The converter keeps the CRANBERRY output names used by the force field:

  • A: P, S3, S2, R1, A1, A2, BC, BN
  • U: P, S3, S2, Y1, U1, Y2, BC, BN
  • G: P, S3, S2, R1, G1, G2, BC, BN
  • C: P, S3, S2, Y1, C1, Y2, BC, BN

The backbone and base beads are copied directly from the atomistic coordinates. BC is the average of the three base beads, and BN is an out-of-plane site built from the base-bead triangle with the same fixed scale used in the legacy utilities.

CLI Split

cranberry cg atomistic_input.pdb --output atomistic_input_cg_vs_conect.pdb
cranberry prepare input_cg_vs_conect.pdb --add-terminal-phosphate

cg coarse-grains atomistic input, then can optionally run the terminal-phosphate repair on the produced CG file. prepare stays a validation-first normalization step for already prepared CG input.

Residual Risk

  • Scope: this is a canonical atomistic-to-CG converter, not a general-purpose RNA cleaning pipeline.
  • Heuristic geometry: BC/BN placement remains a fixed heuristic, not a fitted physical model.
  • Documentation: any downstream docs that still describe cg as an alias must be updated before release.
