Spline Force Optimization

This change removes the dominant CUDA overhead in the CRANBERRY high-resolution spline force without changing the regression model. The original CustomNonbondedForce dispatched across 63 ordered Continuous1DFunction objects for every candidate pair. The replacement evaluates one packed Continuous3DFunction and two discrete distance-range lookups.

Implementation

expr = (
    "active*U(type1,type2,node);"
    f"active=step({base_idx_lim - 0.5}-min(type1,type2));"
    f"node=(r-rmin(type1,type2))*{n_nodes - 1}/"
    "(rmax(type1,type2)-rmin(type1,type2))"
)
force.addTabulatedFunction(
    "U",
    mm.Continuous3DFunction(
        n_types_x, n_types_y, n_nodes,
        y_nodes.transpose(2, 1, 0).ravel(),
        0, n_types_x - 1, 0, n_types_y - 1, 0, n_nodes - 1,
    ),
)

Particle types are integer coordinates in the first two table dimensions. The third coordinate maps each pair-specific distance interval to its original 11 spline nodes. OpenMM uses natural cubic interpolation for both the old 1D functions and the new 3D function, so values at integer type coordinates reproduce the original 1D slices.

Legacy Compatibility

The legacy function names concatenated two type indices without a separator. U110 therefore named both (1, 10) and (11, 0). OpenMM resolved the former through the later (11, 0) registration. A per-type diagnostic localized the entire naive packed-table energy difference to this one collision: 4.3640858129 kJ/mol on 1l2x. The helper _legacy_compatible_spline_tables() reproduces duplicate-name resolution explicitly before packing, rather than relying on duplicate OpenMM function names. 

source_by_name = {f"U{i}{j}": (i, j) for i, j in active_pairs}
for i, j in active_pairs:
    source_i, source_j = source_by_name[f"U{i}{j}"]
    effective_y[i, j] = y_nodes[source_i, source_j]
    effective_x[i, j] = x_lim[source_i, source_j]

Risk Notes

The implementation retains one CustomNonbondedForce, the existing interaction group, three-bond exclusions, 2 nm cutoff, periodic switch, force name, and force group. The packed table assumes integer particle type parameters and uniform node spacing, both of which are properties of the packaged canonical model. The existing four-fixture energy regression remains the authoritative scientific gate.
