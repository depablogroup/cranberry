CRANBERRY CG BN Placement And Output Name Fix

Developer review note for the coarse-graining bug fix tied to GitHub issue #14 and the CLI default output-name mismatch reported during local testing.

What Changed

  • cranberry/cg.py: converted the BN virtual-site cross-product scale from the legacy Angstrom convention to Cranberry's nanometer coordinate convention.
  • cranberry/cli/main.py: stopped overriding the library default output path for cranberry cg, so the CLI now writes <input>_cg_vs_conect.pdb by default.
  • tests/test_cg.py: restored BN to the 1zih coordinate regression and added an API-level default-output-name regression.
  • tests/test_cli.py: added a CLI-level default-output-name regression.

Important Code Paths

# cranberry/cg.py
# Legacy virtual-site placement used coordinates in Angstrom with a 0.1 scale.
# Cranberry stores OpenMM positions in nanometers, so the equivalent scale is 1.0.
_BN_CROSS_PRODUCT_SCALE = 1.0
...
return cog + _cross(p2 - p1, p3 - p1) * _BN_CROSS_PRODUCT_SCALE
# cranberry/cli/main.py
def _cg(args):
    output_path = args.output
    result = coarse_grain_structure(args.pdb, output_path=output_path, ...)

The library already owned the canonical default name. Passing None from the CLI keeps that single source of truth instead of rebuilding a shorter _cg.pdb name in the wrapper.
